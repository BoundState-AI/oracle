## 3. Where the work stands

### `oracle/tailor/` — the product (works, reviewed, not fixed)

`session.py` (cursor + decisions, resumable, atomic save) · `advisor.py`
(brief → ask → propose, `claude-sonnet-5`) · `cli.py` (`py -m oracle.tailor`) ·
`TailorTab.tsx` + `/oracle/tailor/*` routes.

The interaction is: here's AMR-N → here's what it requires and what it's *for* →
do you meet it? → your answer in your own words → advisor maps it to a code and
drafts the rationale → record → next. The order is load-bearing: proposing a code
first invites rubber-stamping a clause the user hasn't read.

**Atlas reviewed it 2026-07-29 on `gpt-5.6-sol`: FIX FIRST, 5 High / 8 Medium /
2 Low. Nothing has been fixed yet.** Two claimed invariants held (no model-write
path; LOW-band downgrade to OPEN). Four broke:

1. **Blank rationale can stick** — `record()` rejects it, `resume()` doesn't.
   `Decision.from_dict` defaults rationale to `""`.
2. **Counts can be wrong** — duplicate/blank requirement IDs collapse rows, so
   two rows show one decision. Same wrong-count outcome as fixture case 22,
   which is the case cited as the *reason* counts are computed.
3. **Advisor failure returns 500, not 502** — `_ensure_client()` sits outside
   `complete()`'s try block.
4. **Save is atomic but not crash-durable** — no `fsync` before `os.replace`.

Plus, separately: **the React stale-response guard is a no-op.** It compares
`b.unit_id` to the captured `req.id`, which always match by construction. Real
consequence: slow brief on AMR-1, navigate to AMR-2, AMR-1 lands and renders
under AMR-2; clicking a code records AMR-2 using AMR-1's advice.

Design-level, held for a decision rather than fixed: pack-boundary bypass
(`/tailor/start` builds a filesystem path instead of using the verified pack
loader — the path-traversal half is a real fix, the "require a promoted pack"
half is a product call); no enforcement of code-specific fields (`NA` with
rationale "seems irrelevant" is accepted though the vocabulary demands a scope
citation); §8 case-19 paired-unit consistency unimplemented; CLI still on the
old propose-only flow while the web UI does brief→ask→propose.
